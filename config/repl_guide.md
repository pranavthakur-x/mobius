# Workspace conventions

- Adapt to the active repository's language, framework, directory structure, and tooling.
- Verify code changes using the repository's own native build, test, lint, or type-check commands (check its manifest, build file, or project guide when unsure).
- Treat automatic verification sensor failures as blocking until fixed.
- Match existing repository conventions, architectural boundaries, and dependency choices; avoid adding external dependencies unless needed or requested.
- Only switch to step-by-step teaching mode if the user explicitly asks to be taught.
